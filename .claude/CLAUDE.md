## Project Overview

A full-stack **content marketing dashboard** with:
- **Blog generation** from CSV files via OpenAI + async Celery jobs
- **SEO tracker** — keyword rankings via SERP scans
- **SEO meta optimizer** — AI-generated meta titles/descriptions per page
- **Website auditor** — crawl-based technical SEO issue detection
- **WordPress publishing** — push blogs to connected WordPress sites

**Architecture pattern**: FastAPI backend with Celery job queues, Next.js frontend with API-route proxying to backend, all backed by Supabase PostgreSQL.

## Development Commands

### Frontend (Next.js)

```bash
cd frontend
npm install
npm run dev          # localhost:3000
npm run build
npm run lint
```

### Backend (FastAPI)

```bash
cd backend
source venv/bin/activate
uvicorn app.main:app --reload    # localhost:8000 — docs at /docs
```

### Background Worker (Celery)

```bash
brew services start redis        # Redis required first
cd backend && source venv/bin/activate
celery -A app.worker.celery_app worker --loglevel=info
```

## Architecture Overview

### Backend (FastAPI + Celery)

**Feature modules** — 6 features, each with the same structure:
```
features/<feature>/
  router.py       - FastAPI APIRouter (HTTP endpoints)
  schemas.py      - Pydantic request/response models
  mappers.py      - dict-to-schema conversion
  services/       - pure business logic (no HTTP)
  worker/         - Celery task definitions (where applicable)
```

Features: `auth`, `blogs`, `seo_tracker`, `seo_meta`, `settings`, `website_audit`

**Shared services**:
- `services/openai/` — shared OpenAI client (used by blogs + seo_meta)
- `services/crawler/` — web crawler used by website_audit (analyzer.py, reporter.py)

**Core modules**:
- `app/main.py` — FastAPI app, CORS, router registration
- `app/core/config.py` — Pydantic Settings (env vars)
- `app/core/dependencies.py` — `require_user_id`, `utc_now_iso`
- `app/db/models.py` — all SQLAlchemy models (monolithic)
- `app/db/session.py` — DB session factory
- `app/api/router.py` — root router including all feature routers
- `app/api/system.py` — auth + storage endpoints
- `app/worker/tasks.py` — re-exports all Celery tasks from feature workers

**Database models** (Supabase PostgreSQL via SQLAlchemy):
User, AuthRefreshToken, CsvUpload, CsvRow, Job, Blog, WordPressSite, BlogPublication, BlogImage, CustomerWebsite, WebsiteKeyword, SerpScan, SerpScanResult, WebsiteMetaRun, WebsiteMetaPage, BlogGenerationSettings, UserAISettings, WebsiteAudit, AuditPage

### Frontend (Next.js 16.2.2, React 19)

- **Route groups**: `(auth)/` for login/signup, `(protected)/dashboard/` for all app pages
- **Auth**: Supabase SSR; route protection in `src/proxy.ts` (Next.js middleware — named `proxy.ts`, not `middleware.ts`)
- **API proxying**: `src/app/api/*` routes forward to FastAPI backend
- **UI**: Radix UI primitives + Tailwind CSS v4

**Dashboard sections** (under `src/app/(protected)/dashboard/`):
- `blogs/` — CSV upload, blog list, individual blog editor
- `blogs/settings` — blog generation settings
- `seo/tracker/` — keyword rank tracking
- `seo/meta-generator/` — meta optimization runs
- `audit/` — website audit crawler
- `settings/` — user/account settings

**API proxy routes** (under `src/app/api/`):
`audit`, `auth`, `blogs`, `csv`, `publications`, `seo`, `settings`, `wordpress`

## Next.js Development with MCP

**When working on the Next.js frontend, call the `init` tool from next-devtools-mcp first.**

Workflow:
1. `init` — establishes context
2. `nextjs_docs({ action: "search", query: "..." })` — find docs
3. `nextjs_docs({ action: "get", path: "..." })` — retrieve full content
4. `nextjs_index` — discover running dev servers
5. `nextjs_call` — query runtime state (errors, logs, routes)

## Key Constraints

- Blog generation status flow: `pending` → `processing` → `completed`/`failed`
- Redis must be running before starting the Celery worker
- Backend port 8000, frontend port 3000; CORS configured for localhost:3000
- No automated tests — manual testing only
